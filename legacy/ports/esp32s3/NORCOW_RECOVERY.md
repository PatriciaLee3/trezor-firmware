# ESP32 NORCOW 提交与恢复协议

这是经确认增加的 ESP32 专用例外：`storage/norcow.c` 只在 `ESP32S3` 条件下调用
端口协议，其他平台保留原算法。仍使用原 NORCOW 条目布局、两个 28 KiB 区域和
`NORCOW_HEADER_LEN=0`；设备盐页不参与日志或提交，不增加额外 Flash 分区。

## 提交顺序

目标区首先被完全擦除并验证，然后写入 `~NORCOW_VERSION`，最后写 PREPARED magic。
复制条目期间，Flash 端口验证每次写入成功。全部条目复制结束（或整个上层版本迁移
明确调用 `norcow_upgrade_finish()`）后，才执行以下顺序：

1. PREPARED `0xF243524E` → READY `0xB243524E`，清除一个 bit，构成持久提交点。
2. 将旧区域 magic 清零使其失效，再逐页擦除旧区域并验证整个区域为空。
3. READY → 标准 NRC2 `0x3243524E`，清除另一个 bit，然后才允许后续钱包写入。

READY 之前，源区域的头和条目没有被压缩/迁移修改。READY 之后，目标区域已经包含
完整副本；直到旧区域擦除完毕之前，目标始终保留 READY。只要观察到单个受支持的
READY，启动就完成该副本的清理与标准化，不依据区域编号猜测新旧。

| 启动状态 | 处理 |
|---|---|
| 一个 NRC2，另一个为未提交数据 | 使用 NRC2；未提交目标只在下次准备写区时擦除 |
| 一个 READY，另一个是旧副本/擦除中的旧区 | 完成旧区擦除，READY 变为 NRC2 |
| 两个 NRC2，或两个 READY | 拒绝启动并保留原数据，不推测历史 |
| 无完整副本，但两个条目区均为空且头是本版本初始化的可识别中间态 | 重试空盘初始化 |
| 无完整副本且有无法识别的非空数据，或已识别头的版本不受支持 | 拒绝启动并保留原数据 |

READY 的版本不得低于同时存在的 NRC2 版本；版本范围为本端口首版 6 到当前上游
`NORCOW_VERSION`。刷入不支持较新存储版本的固件不会触发自动降级擦除。

## Wipe 与升级

Wipe 使用空目标区作为新副本。提交点之前断电，旧钱包仍完整；提交点之后重启会完成
擦除。Wipe 返回之前必须完成旧数据清理。两种情况都保留设备盐，不承诺提交点之前的
Wipe 已经完成。钱包应用层 Wipe 后的重新初始化仍使用上游逻辑。

版本升级期间，只有当前 RAM 中的写目标允许把 PREPARED 作为可写的临时 NORCOW。
读取仍指向旧区；重启不会把 PREPARED 当作已升级的存储。目标不足以容纳迁移结果时
立即停止，禁止压缩覆盖唯一的旧副本。未来升级仍需针对实际的新版本转换逻辑验收；
当前测试中的版本 7 只是测试编译配置，不进入固件。

## 故障模型与验证边界

`tests/test_storage.c` 直接编译原 NORCOW 和真实端口存储实现，只替换 ESP Flash API。
测试两种压缩方向，包含删除条目、零长度值和持久计数器；保留最初“第 24/244 阶段
丢失已有键”的完整压缩触发回归。并对每个可达 READY 快照的恢复步骤再次注入断电。

写入断点包括每次操作前后，以及按正/反位序清除的每个改变位；擦除断点包括半页和
正/反方向的 512 字节片段。测试初始化、压缩、Wipe、模拟 6→7 迁移及迁移容量失败。

此协议不把普通 `norcow_set()`、原地计数器更新或跨多个键的钱包操作改造成原子事务。
这些操作继续使用上游写入和存储认证语义；中断的新条目不保证旧/新值二选一。
压缩触发附带新条目写入的测试仅保证已有无关键保持不变，不将半写入的新条目宣称为
有效提交。任意损坏的原有源区、任意位故障组合、掉电后的 Flash 电气稳定性及完整
钱包 API 的断电行为仍需单独验证。没有新增抗物理篡改能力，不能用于生产资产。
